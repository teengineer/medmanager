# medmanager — project context for Claude

Read this before making changes. It captures what's here, why it's here, and the gotchas that already bit us once.

## What this is

Installable **PWA** for household medicine inventory. Users log medicines (name, expiry, when opened, which conditions they treat) so at the doctor they can say "I already have this" and avoid a redundant prescription. Purpose: reduce medicine waste and public-health spending.

**Market**: Turkey first. UI is TR (default) + EN from day one.

## Stack (locked in — do not swap without asking)

| Layer | Choice |
|---|---|
| Web | React 18 + Vite 6 + TanStack Router (file-based) + TanStack Query + Tailwind + `vite-plugin-pwa` + `react-i18next` |
| API | .NET 10 + **FastEndpoints** (vertical slices) + EF Core + **SQLite** |
| Web host | Netlify (production) |
| API host | **Self-hosted** on user's Linux box via Docker + Caddy (HTTPS) + Litestream (SQLite → S3 backup) |
| Package managers | pnpm 10 (workspace), dotnet CLI |

**Why these:**
- **PWA over Capacitor** — no App Store fees, no review cycles, ship instantly.
- **SQLite over Postgres** — simplicity for v1; Litestream planned so a future Postgres migration stays open.
- **FastEndpoints over Minimal APIs** — user chose it for FastAPI-like DTOs + validators + vertical-slice layout.
- **Self-host** — user's explicit preference; specific server (VPS / home / NAS) still undecided.

## Running locally

```bash
pnpm install                    # workspace install (root)
dotnet restore apps/api/MedManager.sln

pnpm dev                        # web → http://localhost:5173
pnpm api:dev                    # api → http://localhost:5080
pnpm api:test                   # xUnit suite
```

Web proxies `/api/*` → `http://localhost:5080` (configurable via `VITE_API_BASE_URL`).

## Conventions

### Web
- **File-based routes only** — new page = new file under `src/routes/`. Do NOT edit `routeTree.gen.ts`; it's regenerated by `tsr generate` (runs automatically via `pnpm build` or `pnpm dev`).
- **Every feature lands with both TR and EN i18n keys in the same change.** No bare strings in JSX — use `t("key")`. Users land on TR by default; English is the fallback.
- `import.meta.env.VITE_*` for env access; `vite-env.d.ts` already has the client types reference.
- Tailwind only; no other CSS frameworks. Brand color token is `brand` / `brand-dark`.
- TanStack Query `staleTime: 30s` default; tune per query if needed.

### API
- **Vertical slices**: one folder per endpoint under `Features/<Area>/<Action>/`, containing `Endpoint.cs` + `Request.cs` + `Response.cs` + (optional) `Validator.cs`. Changing an endpoint touches exactly one folder.
- Endpoints inherit `Endpoint<TReq, TRes>` or `EndpointWithoutRequest<TRes>`; configure route in `Configure()`, handle in `HandleAsync()`.
- Validators derive from `Validator<TRequest>` — FastEndpoints auto-discovers them.
- **`TreatWarningsAsErrors` is on for the API project.** Build has to stay clean.
- Every API response that references "effective expiry" must compute it server-side as `min(expiry_date, opened_at + opened_shelf_life_days)` — never trust the client.
- EF Core migrations live under `Data/Migrations/`. `dotnet ef migrations add <Name> --project apps/api/MedManager.Api` / `dotnet ef database update`.
- **No Postgres-specific SQL** — SQLite is the target. Dates as ISO-8601 text, GUIDs as text, no `JSONB`.
- Assume **single API instance** (SQLite locks). Don't introduce work that requires horizontal scaling.

### Privacy
- Health data. KVKK + GDPR applies. No third-party analytics or trackers. No medicine names in logs.
- `/me/export` + `/me` DELETE must always work.

## Gotchas we've already hit

1. **`tsr` CLI is per-package, not per-workspace.** `pnpm build` at the web app's directory works. Running from repo root needs `pnpm --filter web build`.
2. **xUnit v3, not v2.** `FastEndpoints.Testing` requires xunit.v3 — mixing in the old `xunit` 2.x package causes `CS0433` ambiguous type errors.
3. **`vite-env.d.ts` is required** for `import.meta.env` and `*.css` imports to typecheck.
4. **`routeTree.gen.ts` is in `.gitignore`** — the plugin regenerates it. Don't panic when it looks uncommitted.
5. **.NET 10 SDK** is what's installed here; `TargetFramework=net10.0` across both projects. Don't downgrade to net9 without checking compatibility.
6. **pnpm v10 ignores build scripts** by default (esbuild warnings on install). Prebuilt binaries are used — the warning is harmless.
7. **`db.Entry().Collection().Query().Include(...)` needs `using Microsoft.EntityFrameworkCore;`** in the feature file — the Include extension isn't in the parent namespace.
8. **`--no-build` on `dotnet test` uses the existing assembly.** If you added a new test class and tests aren't being discovered, drop `--no-build` or clean `bin/obj` first. (Hit this when `MedicineTests` seemed invisible.)
9. **Test parallelism is off** (`xunit.runner.json` sets `parallelizeTestCollections: false`). The tests share an in-memory SQLite via `TestAppFactory`; running in parallel caused non-deterministic JWT/cookie flakes in Release. Don't re-enable without redesigning the fixture.
10. **`webPush` endpoint size**: if you add fields to `PushSubscriptionEntity`, bump the column sizes (Endpoint up to 1024, P256dh 256, Auth 128) — real Push endpoints from FCM/APNs are long.

**Theme**: brand color is **Turkish flag red `#E30A17`** (see `tailwind.config.ts`, `vite.config.ts` `theme_color`, `index.html` meta). `brand-light` is used for pill/tag backgrounds. White backgrounds everywhere else. The home-screen icon block is the red-and-white crescent from `public/favicon.svg`.

**Google OAuth flow** (Phase 1+ addition):
- **No server-side client secret.** Uses the fotografcom-api pattern: client obtains an OAuth access token via `@react-oauth/google` with `flow: "implicit"`, POSTs it to `/auth/google`, server validates by calling `https://www.googleapis.com/oauth2/v1/userinfo?access_token=...`, then issues normal medmanager tokens.
- Needs `VITE_GOOGLE_CLIENT_ID` (public, OAuth 2.0 Web Client) in the web `.env`. User creates this in Google Cloud Console; button is hidden when the env var is missing.
- Users created via Google have `PasswordHash = ""` — they can't log in with password and that's intentional. If they want a password later, add a "set password" flow.

**Web Push** (Phase 4):
- VAPID keypair in `Push:{PublicKey, PrivateKey}` config. **Without these set, push endpoints still work but `ExpiryNotifier` skips ticks and client never shows the enable button.** Generate with `npx web-push generate-vapid-keys`.
- `ExpiryNotifier` is a `BackgroundService` that runs daily at 09:00 UTC, finds medicines expiring in {30, 7, 1, 0} days, and sends push per subscription. Gone/404 responses auto-prune dead subscriptions.
- Service worker (`apps/web/src/sw/sw.ts`, built via `injectManifest`) handles `push` and `notificationclick` events. Switched away from Workbox's `generateSW` for this reason — keep changes to SW minimal and small.
- iOS quirk still applies: Web Push on iOS needs the PWA installed to home screen (iOS 16.4+).

**Auth model** (as of Phase 1):
- Access token: JWT, 15 min, sent as `Authorization: Bearer ...`. Created by `TokenService.CreateAccessToken` using `FastEndpoints.Security.JwtBearer.CreateToken`.
- Refresh token: 32-byte random, SHA-256 hashed in DB (`RefreshTokens` table), delivered as httpOnly cookie `medmanager.rt` (Lax, Path=/, `Secure` in prod only — **not in Development or Testing envs**, otherwise test client can't send it back).
- Rotation: every `/auth/refresh` revokes the old token and issues a new pair.
- JWT validation uses `Configure<JwtBearerOptions>` with `IOptions<JwtOptions>` — **do NOT snapshot `Jwt:SigningKey` at `ConfigureServices` time**. The test factory overrides config via `ConfigureAppConfiguration` which runs at `Build()`; snapshotting earlier causes a signing-key mismatch between issuance and validation (bit us once in Phase 1).
- Web auth flow: access token held in memory only (`auth.token` in `lib/api/client.ts`), refresh via cookie. `api()` wrapper auto-retries once on 401 by hitting `/auth/refresh`. Protected route group is `_authenticated.tsx` which calls `refreshTokens()` in `beforeLoad`.
