# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Read this before making changes. It captures what's here, why it's here, and the gotchas that already bit us once.

## What this is

Installable **PWA** for household medicine inventory. Users log medicines (name, expiry, when opened, which conditions they treat) so at the doctor they can say "I already have this" and avoid a redundant prescription. Purpose: reduce medicine waste and public-health spending.

**Market**: Turkey first. UI is TR (default) + EN from day one.
**Branding**: App name is **MedManager** (capitalized M, M). Repo/package names stay lowercase (`medmanager`, `@medmanager/api`). GitHub: `github.com/teengineer/medmanager`.

## Stack (locked in — do not swap without asking)

| Layer | Choice |
|---|---|
| Web | React 18 + Vite 6 + TanStack Router (file-based) + TanStack Query + Tailwind + `vite-plugin-pwa` + `react-i18next` |
| API | **Hono** (TypeScript) + **Drizzle ORM** + SQLite (via `@libsql/client`, compatible with Turso) |
| Auth | JWT via `jose` (HS256) + BCrypt (`bcryptjs`) + refresh cookie rotation + Google OAuth (token-validate pattern) |
| Web Push | `web-push` npm, VAPID config in env |
| Web host | **Netlify** (`apps/web/netlify.toml` pre-configured) |
| API host | Self-hosted Docker (VPS, Railway, Fly.io, etc.) — Dockerfile at `apps/api/Dockerfile` |
| Package manager | pnpm 10 workspace |

**Why these:**
- **PWA over Capacitor** — no App Store fees, no review cycles, ship instantly.
- **Hono over .NET** — the API was originally .NET 10 + FastEndpoints (see `apps/api-dotnet-archive/`); migrated to TypeScript so the whole repo is one language and deployment is simpler (Node process, Netlify/Railway/Fly compatible).
- **Drizzle + libsql** — local SQLite file for dev/self-host; same code works with managed Turso in prod with a URL swap.
- **Self-host or Railway/Fly** — user's preference is single Node process, SQLite volume.

## Running locally

```bash
pnpm install                             # workspace install

# First-time DB setup (creates medmanager.db in apps/api, seeds use-cases)
pnpm api:migrate

# Two terminals
pnpm dev                                 # web → http://localhost:5173
pnpm api:dev                             # api → http://localhost:5080

pnpm test                                # vitest suite (19 tests, ~11s)
pnpm typecheck                           # all packages
pnpm lint                                # all packages (eslint)
pnpm build                               # all packages
pnpm api:generate                        # regenerate drizzle migration after schema edits

# Single test file or test name (vitest)
pnpm --filter @medmanager/api test tests/medicines.test.ts
pnpm --filter @medmanager/api test -- -t "creates a medicine"
pnpm --filter @medmanager/api exec vitest                # watch mode
```

Web proxies `/api/*` → `http://localhost:5080` (configurable via `VITE_API_BASE_URL`).

## Conventions

### Web
- **File-based routes only** — new page = new file under `src/routes/`. Do NOT edit `routeTree.gen.ts`; it's regenerated by `tsr generate` (runs automatically via `pnpm build` or `pnpm dev`).
- **Every feature lands with both TR and EN i18n keys in the same change.** No bare strings in JSX — use `t("key")`. Users land on TR by default; English is the fallback.
- `import.meta.env.VITE_*` for env access; `vite-env.d.ts` already has the client types reference.
- Tailwind only; no other CSS frameworks. Brand color token is `brand` (`#E30A17`) / `brand-dark` / `brand-light`.
- TanStack Query `staleTime: 30s` default; tune per query if needed.
- Every sub-page has a `<BackButton />` (ghost circular icon, calls `window.history.back()`). Home has none.

### API (Hono + Drizzle)
- **One route file per feature** under `src/routes/`. Mount in `src/app.ts`.
- Every authenticated route declares `requireAuth` **inline** on the route definition (`router.get("/me", requireAuth, ...)`). **Do NOT use `router.use("*", requireAuth)`** — when the sub-router is mounted at `/`, that catch-all leaks into other routers mounted at `/` and breaks public endpoints. This bit us once — tests caught it.
- Validation: `zValidator("json" | "query", schema)` with Zod schemas at the top of the route file. Error handler in `app.ts` converts `ZodError` → 400 with `{ errors: [{ field, message }] }`.
- `c.req.param("X")` can be `undefined` under `noUncheckedIndexedAccess`. Default with `?? ""` or guard.
- Every medicine response computes `effectiveExpiry` server-side (`min(expiryDate, openedAt + shelfLife)`) — never trust the client. Use `effectiveExpiryOf()` and `toMedicineDto()` helpers in `lib/medicines.ts`.
- DB dates stored as ISO strings (TEXT). `dateString` zod regex enforces `YYYY-MM-DD` on inputs.
- Drizzle migrations generated via `pnpm api:generate` and committed. Run `pnpm api:migrate` to apply + seed locally.

### Privacy
- Health data. KVKK + GDPR applies. No third-party analytics or trackers. No medicine names in logs.
- `/me/export` + `DELETE /me` must always work.

## Gotchas we've already hit

1. **Don't use `router.use("*", requireAuth)`** (see above). Inline `requireAuth` on each protected route.
2. **Drizzle Kit v0.30+** uses `dialect: "turso"` for remote, `dialect: "sqlite"` for local. See `drizzle.config.ts`.
3. **`noUncheckedIndexedAccess: true`** is on in tsconfig — `c.req.param("id")` returns `string | undefined`. Guard.
4. **vitest `pool: "forks", singleFork: true`** — tests share a single module-level DB instance so we avoid race conditions on the in-memory SQLite.
5. **Refresh cookie `Secure`** is disabled in dev and test (test client uses HTTP). `lib/cookies.ts:isSecure()` handles this.
6. **Google OAuth doesn't need a server secret** — uses implicit flow. Client sends `accessToken`, server validates via `googleapis.com/oauth2/v1/userinfo`. Same pattern as fotografcom.
7. **`routeTree.gen.ts` is in `.gitignore`** — the TanStack plugin regenerates it.
8. **Brand color is `#E30A17`** (Turkish flag red) — if Tailwind config changes don't show up, restart the Vite dev server (config changes aren't picked up by HMR).

## Ground rules for Claude

- **Never run `git commit` / `git push` / `git init` unless the user asks in that turn.** They're explicit about this.
- Don't add features, abstractions, or error handling the task doesn't require.
- Prefer editing existing files over creating new ones.
- When a decision is ambiguous, pick a sensible default and move on — the user wants forward momentum, not questionnaires.
