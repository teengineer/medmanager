# CLAUDE.md

Bu dosya Claude Code için projeye özel rehber.

## Ne bu

Installable **PWA** for household medicine inventory. Users log medicines (name, expiry, when opened, which conditions they treat) so at the doctor they can say "I already have this" and avoid a redundant prescription. Purpose: reduce medicine waste and public-health spending.

**Market**: Turkey first. UI is TR (default) + EN from day one.
**Branding**: App name is **MedManager** (capitalized M, M). Repo/package names stay lowercase.

## Stack (locked in — do not swap without asking)

| Layer | Choice |
|---|---|
| Framework | **TanStack Start** (`@tanstack/react-start`) — full-stack React, SSR, file-based routes, server functions / API routes |
| Frontend | React 19 + TanStack Router (file-based) + TanStack Query + Tailwind v4 + `vite-plugin-pwa` + `react-i18next` |
| Backend (same app) | Server functions + API routes under `src/routes/api/`. Drizzle ORM + libsql (SQLite local / Turso remote). |
| Auth | **Better Auth** (`better-auth`) with Drizzle adapter. Email/password + Google OAuth. Sessions via cookies. |
| Web Push | `web-push` npm, VAPID config in env |
| Build / runtime | Vite 7, Node 22, single Node process (`server.mjs`) |
| Deploy | Netlify (SSR + API in same function); cron via Netlify Scheduled Function |
| Package manager | pnpm 10 workspace |

**Why these:**
- **TanStack Start** — frontend ve backend tek uygulamada, tek deploy, aynı dilde tip güvenliği.
- **Better Auth** — email verify, password reset, 2FA, magic link "ücretsiz". Sıfır kullanıcı varken risk yok.
- **Tailwind v4** — CSS-first config, ~10x build hızı.
- **Drizzle + libsql** — local SQLite for dev/self-host; same code with managed Turso in prod via URL swap.

## Conventions

### Routes
- **File-based only**. New page = new file under `src/routes/`. `routeTree.gen.ts` is auto-generated by the Start plugin.
- **API routes** under `src/routes/api/` use `createFileRoute(...).server.handlers.{GET,POST,...}`. Each handler receives `{ request, params }`.
- For dynamic segments use `$param` in filename.
- **Better Auth handles `/api/auth/*` entirely.** Don't add custom routes there — use Better Auth options instead.

### Auth
- Server: `auth.api.getSession({ headers: request.headers })` — call this at the top of every protected handler. Returns `null` when unauthenticated.
- Client: `useSession()` from `~/lib/auth-client` for reactive session state. `signIn.email`, `signUp.email`, `signOut`, `signIn.social` for actions.
- Custom user fields (firstName, lastName, locale, timeZone) declared in `lib/auth.ts` `user.additionalFields`.
- Route guard: `_authenticated.tsx` checks `context.session` in `beforeLoad`, redirects to `/login` if absent. Session is loaded once in `__root.tsx` `beforeLoad`.

### DB / Drizzle
- Schema lives in `src/db/schema.ts`. Better Auth's tables (user, session, account, verification) come first; domain tables follow.
- After schema changes: `pnpm db:generate` (creates SQL migration), then `pnpm db:migrate` (applies + seeds).
- Dates: ISO strings (TEXT) for domain tables; Better Auth uses Date objects (timestamp mode).

### Tailwind 4
- Single CSS file: `src/styles/app.css` — `@import "tailwindcss"` + `@theme` block for custom tokens.
- Brand color tokens: `--color-brand`, `--color-brand-dark`, `--color-brand-light` → use as `bg-brand`, `text-brand`, etc.
- No `tailwind.config.ts`, no `postcss.config.js` — `@tailwindcss/vite` plugin handles everything.

### i18n
- Every feature lands with TR + EN keys in the same change. No bare strings in JSX — use `t("key")`.
- Default locale: TR. English is fallback.

### Privacy
- Health data. KVKK + GDPR applies. No third-party analytics or trackers. No medicine names in logs.
- `/api/me` DELETE + `/api/me/export` always work.

## Deployment

- **Netlify only** (web + API in same SSR function).
- Required env vars (Netlify dashboard):
  - `DATABASE_URL` — Turso libsql URL (e.g. `libsql://...turso.io`)
  - `DATABASE_AUTH_TOKEN` — Turso token
  - `BETTER_AUTH_SECRET` — long random (Better Auth signs sessions with this)
  - `BETTER_AUTH_URL` — production origin (e.g. `https://e-medmanager.netlify.app`)
  - `WEB_ORIGIN` — same as above (added to `trustedOrigins`)
  - `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` — for Google sign-in
  - `PUSH_PUBLIC_KEY`, `PUSH_PRIVATE_KEY`, `PUSH_SUBJECT` — VAPID for web push
  - `CRON_SECRET` — guards `/api/cron/expiry` from public calls
- Migrations run on Node startup via `server.mjs` if `DATABASE_URL` set.
